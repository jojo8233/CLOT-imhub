# 05 权限与团队

## 需求出处

- 设计 §1 目标三:「管理员分组带队,看得到组内员工的账号状态、客户档案与告警」
- 设计 §3:单租户四角色(owner / auditor / manager / agent),查询层统一
  scope 过滤;manager 可带多 team,agent 只属一个 team

## 实现位置

- `packages/server/src/rbac/scope.ts` — `resolveScope`:按角色算可见范围。
  **switch 没有 default 分支**,靠 TS 穷尽性检查保证新增角色不会被漏掉
- `packages/server/src/rbac/scoped-db.ts` — `ScopedDb`:把 actor 的可见
  范围闭包进查询构造器
- `packages/server/src/api/` — 路由**不允许 import db 读业务数据**,只能用
  `req.scoped`——漏过滤在结构上不可能发生,这是「结构性而非检查性」的含义
- `packages/server/src/auth/{password,session}.ts` — 密码哈希、JWT 签发
- `requireOwnedAccount`(accounts 路由内)— 创建/删除账号按 owner 取,
  不走 scoped

## 关键设计取舍

- **RBAC 是结构性的,不是检查性的**:与其在每个路由里记得加 where,不如
  让「不加」编译不过/拿不到 db。
- **创建/删除刻意绕开 scoped**:scoped 语义是「能看见」,而这两个操作要求
  「是本人的」——用 scoped 会让 manager 能替下属完成登录、拿走他的账号。
- **`Actor.leadTeamIds` 每请求实时查,不缓存进 JWT**:带队关系变了,旧
  token 不应该继续放大权限。
- 客户端侧 JWT 只在渲染进程模块变量里,持久化走 `safeStorage`(OS 钥匙串),
  绝不明文落盘。

## 已知限制
